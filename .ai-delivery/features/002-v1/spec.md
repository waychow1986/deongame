# DeonGame 精致化：标准象棋棋盘、真实扑克牌与大厅体验 产品规格

> 依据：已在 G1 确认的意图第 2 版（含 Q1～Q4、R1～R3 的答案）与需求原文 `request.json`。本交付没有 G2 已决定事项（`g2Decisions` 为空）。
> 现状依据：`.ai-delivery/system-current.md`（第一版代码事实）与第一版规格 `.ai-delivery/features/001-v1/spec.md`。
> 来源写法：“AC-n”指本意图的验收标准；“范围 n”指意图范围第 n 条；“意图假设 n”指意图“假设”一节第 n 条；“Q1～Q4、R1～R3”指意图中已由人回答的问题；“原文 一.5”指需求原文第一部分第 5 条。

## 产品目标与边界

- 本版不改任何游戏规则、积分与筹码算法，只改画面与交互，并修正第一版验收发现的错误：象棋棋子不在交叉点、棋盘缺楚河汉界与九宫斜线、红黑暗子无法区分、扑克牌为文字、登录后直接进入上次的房间而回不到大厅。（来源：意图“要解决的问题”、范围 1、范围 6）
- 覆盖的页面：注册、登录、大厅、象棋房间、德州扑克房间；电脑浏览器与手机浏览器（竖屏）都要可用。（来源：范围 2～5）
- 本版新增的用户可见能力：大厅“回到对局”入口、房间内“回到大厅”与“离开房间”的区分、开房间弹窗、可设置的扑克房间人数上限、房间名、音效与静音、各种状态提示。其余能力（注册登录、开房加入、揭棋对局、认输、提和、扑克牌局、电脑对手与电脑玩家、积分与筹码结算）沿用第一版。（来源：范围 1～6、AC-36）

## 参与者与权限

| 参与者 | 说明 | 权限 |
|---|---|---|
| 访客 | 未登录的人 | 只能使用注册、登录页面；访问大厅或房间页面时显示登录页面（来源：AC-4） |
| 用户 | 已登录的人 | 使用大厅、开房间、加入房间、回到对局（来源：范围 2） |
| 房间成员 | 已在某房间中的用户（象棋的红方/黑方，扑克的入座玩家） | 只有房间成员能打开该房间页面并看到对局局面；同一用户同一时间只在一个房间（来源：意图假设 2，沿用第一版） |
| 房主 | 开房间的用户；房主离开后由其余成员接任 | 扑克房间中开始牌局、添加电脑玩家（沿用第一版，来源：意图假设 1、AC-36） |
| 电脑对手 / 电脑玩家 | 象棋人机对局的黑方；扑克房间中房主添加的电脑座位 | 行为沿用第一版，只有一个难度（来源：意图假设 1） |

## 领域术语

- **进行中的对局**：用户仍占有某房间中的一方或一个座位、且该房间尚未结束的状态，具体为：象棋房间处于“等待对手”或“对局中”且用户是其中一方；德州扑克房间中用户仍在座（不论此刻有没有一手牌在进行）。象棋对局一旦结束（任何原因），对该局的双方都不再算“进行中的对局”。（来源：AC-2、Q1、意图假设 2；界定方式见假设 A-1）
- **回到大厅**：只离开房间页面、显示大厅，不退出对局、不让出座位。（来源：Q1）
- **离开房间**：退出房间，沿用第一版的离开规则（象棋对局中即认输，扑克一手牌中即弃牌并让出座位）。（来源：Q1）
- **暗子**：揭棋中盖着、未翻开的棋子。（来源：原文 一.3）
- **简短提示**：页面上显示的一句文字，不需要用户关闭，显示后自动消失。（来源：AC-17、意图假设 8）
- **手机竖屏**：页面宽度 360～430 CSS 像素。（来源：AC-34、意图假设 11）
- **房间名**：“{房主用户名}的房间”。（来源：意图假设 3）

## 用户故事

### US-01 登录后回到大厅，随时能回到对局（P1）
作为用户，我希望登录后先看到大厅，有进行中的对局时能一键回去，在房间里也能随时回到大厅，以便不被困在上一次的房间里。（来源：范围 1、AC-1～AC-3）

### US-02 像样的游戏大厅（P1）
作为用户，我希望在大厅看到自己的信息、两款游戏的卡片和自动更新的房间列表，并通过弹窗开房间，以便从大厅直接开始游戏。（来源：范围 2、AC-4～AC-10）

### US-03 标准的盲棋棋盘与棋子（P1）
作为象棋玩家，我希望看到标准的中国象棋棋盘，棋子落在交叉点上，红黑暗子一眼可分，以便像下真棋一样对弈。（来源：范围 1、范围 3、AC-11～AC-15）

### US-04 清楚的走棋交互与对局结果（P1）
作为象棋玩家，我希望点选棋子即可看到能走的位置，看到走棋动画、将军提示和对局结果，以便流畅地下完一局。（来源：范围 3、AC-16～AC-20）

### US-05 真实的德州扑克牌桌（P1）
作为扑克玩家，我希望在椭圆形绿色牌桌上看到真实的扑克牌、庄家与盲注标记、底池和动画，并在轮到自己时用清楚的操作区行动，以便像在真实牌桌上一样游戏。（来源：范围 4、AC-21～AC-29）

### US-06 统一风格、音效与手机竖屏（P2）
作为用户，我希望所有页面风格统一、有音效且可静音，在手机竖屏上也能完整使用，并在加载、等待、断线时知道发生了什么。（来源：范围 5、AC-30～AC-35）

### US-07 规则不变（P1）
作为老用户，我希望规则、积分和筹码与第一版完全一致。（来源：范围 6、AC-36）

## 功能需求

### 进入大厅与回到对局

- **FR-001**：用户登录成功或注册成功后，页面显示大厅，不会自动进入任何房间；即使该用户上一次停留在房间中、或此刻有进行中的对局，也是如此。（来源：AC-1、原文 一.5）
- **FR-002**：已登录的用户重新打开网站（打开网站地址或大厅地址）时，页面显示大厅，不会自动进入任何房间；有进行中的对局时大厅显示“回到对局”入口（见 FR-003）。（来源：R2 答案）
- **FR-003**：用户在房间页面中刷新页面时，仍停留在该房间页面，并显示对局的当前局面。（来源：R2 答案）
- **FR-004**：用户有进行中的对局时，大厅显示“回到对局”入口；点击后进入该对局所在的房间页面，显示对局的当前局面。用户没有进行中的对局时，大厅不显示该入口。（来源：AC-2、原文 一.5）
- **FR-005**：象棋房间页面和德州扑克房间页面上都有文字为“回到大厅”的操作；点击后页面显示大厅。“回到大厅”不退出对局：象棋对局继续保留、扑克座位继续保留，对局照常进行；轮到该用户走棋或行动时，对局等待该用户回来操作（沿用第一版“不设行动时限”）。该用户在大厅看到“回到对局”入口，可随时返回。（来源：AC-3、Q1 答案）
- **FR-006**：象棋房间页面和德州扑克房间页面上另有一个“离开房间”操作，与“回到大厅”分开显示。点击后先要求用户确认；用户确认后按第一版规则离开房间并显示大厅：象棋对局进行中离开即认输（按负局结算积分），扑克一手牌进行中离开即在该手弃牌、已投入的筹码不退回，并让出座位；用户取消时不发生任何变化，仍停留在房间页面。（来源：Q1 答案、AC-36）
- **FR-007**：用户有进行中的对局时，在大厅不能开新房间、也不能加入其他房间：开房间的入口（游戏卡片）与房间列表中的加入按钮不可用，并以文字说明原因（如“你有进行中的对局”），同时显示“回到对局”入口。（来源：意图假设 2）
- **FR-008**：用户不在房间页面期间，其象棋对局结束（例如对手认输或离开房间）时，该用户不再有进行中的对局：大厅不再显示“回到对局”入口，用户可以开房间、加入房间，大厅顶部显示结算后的最新积分。（来源：AC-2、FR-004；见假设 A-2）

### 大厅

- **FR-010**：大厅页面顶部显示大厅名称“DeonGame”、当前用户的用户名、象棋积分、扑克筹码和“退出登录”操作。扑克筹码为负数时以红色显示，为零或正数时不以红色显示。（来源：AC-4、原文 二）
- **FR-011**：大厅顶部显示的积分与筹码是该用户当前的数值：用户结束一局象棋或一手扑克后回到大厅时，显示结算后的数值。（来源：范围 2“当前用户信息”）
- **FR-012**：点击“退出登录”后页面显示登录页面；此后再访问大厅或房间页面时显示登录页面，要求重新登录。（来源：AC-4）
- **FR-013**：大厅以两张卡片展示“中国象棋·盲棋”和“德州扑克”，每张卡片有一个图标和一句玩法介绍。（来源：AC-5、原文 二）
- **FR-014**：点击任一游戏卡片打开开房间弹窗，弹窗中已选中该卡片对应的游戏类型。（来源：AC-5、意图假设 4）
- **FR-015**：大厅的房间列表中每个房间显示：房间名（“{房主用户名}的房间”，房主变更后显示新房主的用户名）、游戏类型（“中国象棋·盲棋”或“德州扑克”）、当前人数/上限（如“2/6”，扑克房间的人数含电脑玩家）、状态（“等待中”或“对局中”）。（来源：AC-6、意图假设 3、意图假设 5）
- **FR-016**：房间列表包含哪些房间沿用第一版：列出可供他人加入或查看人数的联机象棋房间与扑克房间；与电脑对战的象棋房间不列出；对局已结束的象棋房间不再列出。（来源：AC-36，沿用第一版）
- **FR-017**：房间是否可加入：
  - 象棋房间满员或状态为“对局中”时不可加入，加入按钮置灰并显示原因（“已满员”或“对局中”）；
  - 扑克房间只在满员时不可加入，加入按钮置灰并显示“已满员”；扑克房间状态为“对局中”但有空座位时可以加入，加入后从下一手开始参与；
  - 置灰的加入按钮点击后不会加入房间；可用的加入按钮点击后进入该房间页面。
  （来源：AC-7、Q4 答案）
- **FR-018**：用户点击可用的加入按钮时，若房间在此期间已满员、已开局或已关闭，页面用中文说明不能加入的原因，用户仍停留在大厅，房间列表显示该房间的最新状态。（来源：AC-7、AC-10 的中文出错说明；见假设 A-3）
- **FR-019**：其他用户开房间、加入或离开房间、房间开局或结束、房间关闭后，正在看大厅的用户不需刷新页面，房间列表在 5 秒内显示变化后的房间、人数和状态（关闭或不再列出的房间从列表中消失）。（来源：AC-8、意图假设 6）
- **FR-020**：开房间弹窗包含：游戏类型选择（中国象棋·盲棋 / 德州扑克）；选象棋时的对战方式选择（“联机对战”或“和电脑对战”）；选扑克时的房间人数上限设置（可选 2～9，默认 9）；“确认”和“取消”操作。弹窗不包含房间名等其他选项。（来源：AC-9、原文 二、意图假设 5、意图“不做的事”）
- **FR-021**：在开房间弹窗中点“取消”或关闭弹窗，不创建任何房间，页面仍为大厅。（来源：AC-9；见假设 A-4）
- **FR-022**：在开房间弹窗中点“确认”后：
  - 象棋“联机对战”：创建一个等待对手的房间并进入该房间页面，页面显示等待对手加入的提示；该房间出现在其他用户的大厅列表中，状态“等待中”、人数“1/2”；
  - 象棋“和电脑对战”：直接进入与电脑的对局，用户执红先走；
  - 德州扑克：创建房间并进入该房间页面；该房间在大厅列表中显示的上限为所设人数；房间中真人与电脑玩家合计达到上限后，其他用户不能再加入（加入按钮置灰并显示“已满员”），房主也不能再添加电脑玩家。
  （来源：AC-9、意图假设 5、AC-36 中第一版人机规则）
- **FR-023**：注册页面与登录页面使用与大厅相同的配色、字体和按钮风格。注册或登录出错时，页面用中文写明原因，至少区分：用户名已被占用；用户名或密码错误；输入不符合要求（如用户名或密码为空、超过长度上限，并指出是哪一项）；网络连接失败。（来源：AC-10、原文 二）

### 中国象棋：棋盘与棋子

- **FR-030**：象棋棋盘为木纹底色，画有 9 条竖线和 10 条横线；中间河界处有“楚河”“汉界”文字；双方九宫内各画有两条交叉斜线；双方兵卒与炮的开局位置画有位置标记。（来源：AC-11、原文 一.1～一.2、原文 三）
- **FR-031**：棋盘上每枚棋子（翻开的与盖着的）的中心都落在竖线与横线的交叉点上，没有棋子位于方格中间；走棋后、翻子后也是如此。（来源：AC-12、原文 一.1）
- **FR-032**：浏览器窗口大小改变时，棋盘随之等比缩放：宽高比不变、不变形，棋盘完整显示在页面内，棋子仍落在交叉点上。（来源：AC-13）
- **FR-033**：棋子显示为圆形木质棋子，有立体感和阴影；翻开的红方棋子文字为红色，黑方棋子文字为黑色。（来源：AC-14）
- **FR-034**：暗子背面朝上，不显示其实际身份；同一局面中红方暗子与黑方暗子的背面颜色或边框明显不同，不看所在位置也能分清是哪一方的暗子；双方用户看到的区分方式相同。（来源：AC-15、原文 一.3、意图假设 7）

### 中国象棋：走棋交互

- **FR-040**：轮到自己时点击自己的一枚棋子（翻开的或盖着的），该棋子高亮为选中，棋盘上用小圆点标出它所有可走的位置；标出的位置与盲棋规则允许的位置完全一致（盖着的棋子按所在位置的开局棋子类型计算，翻开的棋子按实际身份计算，走后会被将军或造成将帅照面的位置不标出）。（来源：AC-16、原文 三）
- **FR-041**：已选中一枚棋子时：点击另一枚自己的棋子，改为选中该棋子并重新标出可走位置；再次点击已选中的棋子，取消选中，小圆点消失。（来源：AC-16、AC-17；见假设 A-5）
- **FR-042**：选中棋子后点击一个标有小圆点的位置（含有对方棋子的位置，即吃子），棋子走到该位置，选中与小圆点随即消失。（来源：AC-17）
- **FR-043**：以下情况页面显示一句简短提示，且不落子：
  - 已选中棋子时点击没有小圆点的位置（如“这里不能走”）；
  - 未选中棋子时点击对方的棋子（如“这是对方的棋子”）；
  - 不是自己的回合时点击棋子（如“还没轮到你”）；
  - 走棋提交后未被接受（如对局已结束、局面已变化），页面显示原因，棋子回到走棋前的位置并显示最新局面。
  （来源：AC-17、意图假设 8）
- **FR-044**：棋盘上每个交叉点的点按区域为以该交叉点为中心、边长等于相邻交叉点间距的正方形；点到这个范围内即视为点中该交叉点（及其上的棋子）。（来源：R1 答案）

### 中国象棋：动画与对局信息

- **FR-050**：任何一方（含电脑对手）走棋时，双方页面上都能看到棋子从起点移动到终点的过程，不是瞬间出现在终点。（来源：AC-18、原文 三）
- **FR-051**：暗子走完一步后，先在终点播放翻面动画，再显示其实际身份。（来源：AC-18）
- **FR-052**：吃子时被吃的棋子以动画消失。（来源：AC-18）
- **FR-053**：上一步走棋的起点和终点在棋盘上有标记，双方都能看到；下一步走棋后标记改为标出新的一步。（来源：AC-18）
- **FR-054**：一方被将军时，双方页面上显示“将军”；解除将军后不再显示。（来源：AC-19、原文 三）
- **FR-055**：对局进行中页面始终显示当前轮到哪一方（红方或黑方），并标明是否轮到自己。（来源：AC-19）
- **FR-056**：双方被吃的棋子以实际身份分别显示在各自一侧：红方被吃的棋子显示在红方一侧，黑方被吃的棋子显示在黑方一侧。（来源：AC-19；见假设 A-6）
- **FR-057**：认输、提和与回应提和等第一版的对局操作在象棋房间中仍可使用，规则不变。（来源：AC-36）

### 中国象棋：对局结果

- **FR-060**：象棋对局结束（将死、困毙、认输、离开即认输、同意和棋、只剩将帅）时，双方页面显示结果画面，内容为：本人视角的“胜”“负”或“和”；本局积分变化（胜“+10”、负“-10”、和“0”）；结算后的最新积分；“再来一局”和“回到大厅”两个操作。人机对局中只对用户显示。（来源：AC-20、原文 三、意图假设 1）
- **FR-061**：积分尚未结算完成时，结果画面在积分处显示结算中的说明；结算完成后不需刷新即显示积分变化与最新积分。（来源：AC-20、AC-36 中第一版结算重试行为；见假设 A-7）
- **FR-062**：在结果画面点“回到大厅”，页面显示大厅，该用户不再在这个房间中，大厅不显示该局的“回到对局”入口。（来源：AC-20、AC-2）
- **FR-063**：在结果画面点“再来一局”：
  - 和电脑对战的对局：直接开始一局新的人机对局，用户执红；

## 前置条件与触发条件

- 大厅、房间页面的前置条件是用户已登录；未登录访问时显示登录页面。（FR-012）
- 打开某房间页面的前置条件是用户是该房间的成员；“回到对局”入口只在用户有进行中的对局时出现。（FR-004）
- 开房间、加入房间的前置条件是用户没有进行中的对局。（FR-007）
- 象棋走棋交互的前置条件是对局进行中且轮到自己；扑克操作区可用的前置条件是一手牌进行中且轮到自己。（FR-040、FR-080）
- 触发事件：登录/注册成功（FR-001）、打开网站或刷新（FR-002、FR-003）、他人改变房间（FR-019）、走棋/行动（FR-050～FR-056、FR-075、FR-076）、对局或一手结束（FR-060、FR-085、FR-086）、连接中断与恢复（FR-096）。

## 行为模型

### US-01 登录后回到大厅，随时能回到对局
- 正常：用户登录 → 显示大厅（FR-001）；有进行中的对局 → 大厅显示“回到对局”→ 点击进入房间、看到当前局面（FR-004）→ 点“回到大厅”→ 显示大厅、对局保留（FR-005）。
- 替代：已登录用户重新打开网站 → 显示大厅（FR-002）；在房间页面刷新 → 仍在该房间（FR-003）。
- 替代：点“离开房间”→ 确认 → 按第一版规则认输或弃牌离座并显示大厅；取消 → 无变化（FR-006）。
- 边界：用户不在房间页面时其象棋对局结束 → “回到对局”入口消失、可开新房间（FR-008）；扑克轮到不在房间页面的用户时，牌局等待其回来（FR-005）。
- 错误：有进行中的对局时开房间或加入 → 不可用并说明原因（FR-007）。

### US-02 像样的游戏大厅
- 正常：看到顶部信息（FR-010、FR-011）、两张游戏卡片（FR-013）、房间列表（FR-015、FR-016）；点卡片 → 弹窗预选游戏 → 确认 → 进入新房间或人机对局（FR-014、FR-020、FR-022）。
- 替代：弹窗中取消 → 不建房（FR-021）；从列表加入可加入的房间（FR-017）。
- 边界：扑克房间“对局中”但有空座位 → 可加入、下一手开始参与；扑克房间人数达上限 → 置灰“已满员”、房主不能再加电脑玩家（FR-017、FR-022）；筹码为负 → 红色（FR-010）。
- 错误与恢复：加入时房间已变化 → 中文说明原因、留在大厅、列表更新（FR-018）；注册/登录出错 → 中文原因（FR-023）；连接中断 → 提示，恢复后列表更新（FR-096）。

### US-03 / US-04 象棋
- 正常：标准棋盘与棋子（FR-030～FR-034）；轮到自己 → 点子 → 高亮与小圆点 → 点小圆点 → 移动动画 → 暗子翻面 → 吃子消失 → 上一步标记（FR-040、FR-042、FR-050～FR-053）；将军、轮次、被吃棋子显示（FR-054～FR-056）。
- 替代：改选另一枚棋子或取消选中（FR-041）；认输、提和（FR-057）。
- 边界：窗口缩放（FR-032）；手机竖屏点按交叉点（FR-044、FR-095）。
- 错误：点错位置、点对方棋子、不是自己的回合、提交未被接受 → 一句简短提示、不落子（FR-043）。
- 结束：结果画面（FR-060、FR-061）→ “回到大厅”（FR-062）或“再来一局”（FR-063）。

### US-05 德州扑克
- 正常：牌桌、座位、牌、标记、底池（FR-070～FR-074）；发牌、下注、翻公共牌动画（FR-075）；轮到的座位高亮（FR-076）；轮到自己 → 操作区高亮 → 选择行动、设定加注额（FR-080～FR-083）。
- 结束：摊牌展示或只剩一人展示（FR-085、FR-086），保持到下一手开始（FR-087）。
- 边界：加注额超出允许范围 → 不能提交（FR-083）；平分底池（FR-085）；一手进行中加入 → 显示“等待下一手”（FR-071、FR-017）。
- 错误：行动未被接受 → 中文原因、显示最新状态（FR-084）。

### US-06 统一风格、音效与手机竖屏
- 正常：统一风格（FR-090）；事件音效（FR-091）；静音切换（FR-092）；手机可听到（FR-093）与静音模式提示（FR-094）；竖屏完整显示（FR-095）；加载、等待对手、重连提示（FR-096）。
- 边界：刷新页面后静音恢复为有声音（FR-092）；手机首次点按前可以无声（FR-093）。

### US-07 规则不变
- 第一版全部规则与验收标准保持通过（FR-100、FR-101）。

## 业务状态、业务数据规则与不变量

- 用户在大厅与房间之间切换（回到大厅、回到对局、刷新页面、重新打开网站）不改变对局状态、座位、积分与筹码；只有“离开房间”（确认后）和对局本身的结束会改变。（FR-005、FR-006）
- 同一用户同一时间只在一个房间。（FR-007，沿用第一版）
- 房间名始终为“{当前房主用户名}的房间”，用户不能修改。（FR-015）
- 扑克房间人数上限在开房间时设定，取值 2～9，默认 9；房间中真人与电脑玩家合计不超过上限。（FR-020、FR-022、FR-101）
- 象棋房间上限为 2；与电脑对战的房间不在大厅列出。（FR-015、FR-016，沿用第一版）
- 积分、筹码只在对局或一手牌结算时变化，变化数值与第一版一致；筹码与积分可为负数。（FR-100）
- 暗子的实际身份在翻开前对任何用户都不显示（含暗子的持有者）；被吃时以实际身份显示。（FR-034、FR-056，沿用第一版）
- 其他玩家的底牌只在摊牌时、且只对参与摊牌的玩家翻开显示。（FR-073、FR-085、FR-086，沿用第一版）
- 静音状态只属于当前页面，不保存。（FR-092，R3 答案）
